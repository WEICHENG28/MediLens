> 测试日期：2026-10-25。**全部为合成数据**（虚构报告，固定随机种子，可复现）；判读规则为**测试规则，未经医学审核**。

## 三、对照实验

### 实验 A：组合规则 vs 通用逐项解读（1000 份随机合成报告）

「通用逐项解读」= 每项与参考范围比较、超出即标异常、无法识别的项目直接不显示、无组合规则、不问用药。

| 指标 | MediLens | 通用逐项解读 |
|---|---|---|
| 单项异常判定一致率 | 100% | 100% |
| 酮症紧急提示召回率（应提示 103 份） | **100%** | 0% |
| 感染干扰提示召回率（应提示 125 份） | **100%** | 0% |
| 用药干扰解释召回率（应解释 116 份） | **100%** | 0% |
| **错误安慰率**：有关键项无法确认，却显示「全部正常」（271 份） | **0%** | **8.5%（23 份）** |

**结论**：两者单项判断完全一致，差异来自**多指标组合判读**与**对「未知」的处理**。通用做法的组合提示为 0 是设计上不具备该功能（能力差异，不是准确率差异）；最关键的差别是通用做法约每 12 份含不确定项的报告就有 1 份会误报「全部正常」。

### 实验 B：局部确认的价值（独立测试集）

| 指标 | 不做局部确认（全部自动接受） | MediLens（局部确认） |
|---|---|---|
| 进入判读的错误字段 | 30 个（3.9%） | **3 个（0.39%）** |
| 用户需要确认的字段比例 | 0% | 11.5%（约每份报告 0.7 个） |
| 被拦截的错误中，候选值可一键改正 | — | 92.6% |

**结论**：用约 11.5% 的确认工作量，把进入医学判读的识别错误减少约 90%。

### 实验 C：越界提问拦截的迭代（规则式意图识别的局限）

| 版本 | 第一轮题目（45 句越界） | 第二轮新题目（44 句越界） |
|---|---|---|
| 第一版（单一关键词） | 57.8% | — |
| 第二版（对象词 × 意图词组合） | 97.8%（已看过题目，不作为成绩） | **59.1%** |

**结论**：规则式意图识别在「见过的说法」上可以很高，但面对新的口语说法会大幅下降，无法达到 100% 目标。这印证了「不能只靠关键词过滤」，下一阶段需加入**语义意图分类**（大模型或分类模型）作为第二层。同时，输出校验作为另一道防线：mock 模式下两轮 89 个越界问题的回答**均不含越界内容**，但未被拦截的问题没有得到「请由医生决定」的安全引导。

### 实验 D（未完成）：MediLens vs 通用大模型直接解读

已取得学校多模型平台接口（2026-10-27 连通），待执行。计划比较：报告外数值（幻觉）比例、越界建议比例、出处覆盖率、对同一报告多次回答的一致性。

### 大模型接入实测（2026-10-27，学校多模型平台）

同一合成报告（尿糖 3+、酮体 2+）、5 个问题，对比无大模型（mock）与 DeepSeek-V4.1-Flash（`tools/compare_llm.py`）：

| 项目 | 结果 |
|---|---|
| 默认（开启推理）响应时间 | 7–23 秒，部分超过 20 秒上限后回退标准说明 |
| 关闭推理（thinking=disabled）后 | **1.6–7.0 秒**，5 题全部由大模型回答，全部通过输出校验 |
| 回答差异 | 改写为口语、分段，并针对问题回应（如「是否严重需医生判断」）；内容未超出规则与知识 |
| 越界问题（「我能停药吗」） | 两种模式相同，由安全模板回答，不经过大模型 |
| 观察项 | 「复诊问什么」时大模型补充了另一条已命中规则（R-06）的问题——有依据，但超出「只改写草稿」，留待实验 D 统计 |

## 四、主要发现与残余风险

1. **最主要的残余风险：数值小数点丢失**。测试集 3 个静默错误全部是此类（UACR 81.1→811、7.8→78，pH 7.7→7），错误值仍在合理范围、置信度接近 1，无法被现有规则发现。UACR 的 81 与 811 属于不同分级，**下一步：关键定量指标（UACR）一律展示原图局部供确认**，并用新测试集验证。
2. **「±」是最难识别的字符**：开发集 52 个错误中 19 个与「±」有关，均被局部确认拦截。
3. **参考范围识别率较低（测试集 79.5%）**：主要是单独的「-」漏检。不影响判读（自动退回字典通用参考并注明来源），但影响「参考范围」展示。
4. **规则式越界拦截无法泛化**（实验 C）。
5. **人工测试发现：繁体输入可绕过安全拦截**（2026-10-25，用注音输入法输入「我能停藥嗎」「藥我不想吃了」均未拦截）。原因是拦截词表只有简体。已修复：后端在安全分类与输出校验前统一做繁→简转换（OpenCC，本地运行不联网）。验证：两轮共 120 句测试题转为繁体后，分类结果与简体版 120/120 一致；另将「不想（吃/打/用）」加入用药决定词（来自本次人工测试，未计入测试集成绩）。
6. 开发集与测试集的差异（错误拦截率 98.1% → 90.0%）说明：**只用调参数据报告成绩会高估效果**，因此本文件所有成绩均取自独立测试集。

## 五、开发集 / 测试集的使用方式

- **开发集**（`tests/eval/dev`，种子 20261025，130 份）：用于分析错误、调整解析规则（形近字匹配、候选生成、确认门槛 0.95→0.85）。
- **测试集**（`tests/eval/test`，种子 77031，130 份）：调整完成后才生成，只评测一次，**不据此修改**。
- 越界问题：第一轮 60 句用于发现问题；第二轮 60 句在拦截器第二版完成后新写，结果不再据此修改。理想做法是由**组员独立编写**测试问题，避免开发者偏差。

开发集与测试集对照：

| 指标 | 开发集 | 测试集 |
|---|---|---|
| 字段识别准确率（确认前） | 91.9% | 93.8% |
| 识别错误拦截率 | 98.1% | 90.0% |
| 静默错误率 | 0.12% | 0.39% |
| 确认负担 | 13.5% | 11.5% |

## 七、复现方法

```powershell
# OCR 评测（生成 → 识别 → 评分）
python tools/eval/gen_eval_set.py test
tools/.venv/Scripts/python -I tools/eval/run_ocr.py test
cd app; dart run tool/eval_ocr.dart test; cd ..           # 结果：tests/eval/test/results/ocr_eval.json

# 规则评测与对照实验 A
backend/.venv/Scripts/python tools/eval/eval_rules.py       # 结果：tests/eval/rules_results.json

# 越界提问（第二轮）
backend/.venv/Scripts/python tools/eval/eval_boundary.py tests/eval/boundary_questions_v2.yaml tests/eval/boundary_results_v2.json

# 端到端计时（需后端与模拟器运行）
cd app; flutter test integration_test/perf_test.dart -d emulator-5554
```

OCR 评测使用与 APP 相同的 ONNX 模型（Python 参考实现识别）+ APP 实际的 Dart 解析器；端侧 Dart 识别与参考实现的一致性已在模拟器上验证（5 份样本结论一致，个别字符有差异，如被遮挡的「2+」端侧识别为「2」，同样被拦截确认）。
