## 0. 给接手模型的直接指令（先读）

你现在是 MediLens MVP 1.0 的产品、交互、移动端、后端与测试协作开发助手。请先完整阅读本文件，把「已确认」当作不可随意更改的约束，**不要再问用户已经回答过的问题**。先输出：①你理解的需求及冲突检查；②必须由用户决策的少数未决问题（仅限真正阻塞实施者）；③架构及分阶段开发方案；④验收用例；⑤你能在当前环境实际操作的范围。经确认后逐模块实施、测试、反馈。不得声称已修改用户本地 Codex 项目、已测试大陆网络或已完成临床审核，除非确实执行并留有证据。

**核心体验目标**：用户以拍照为主输入尿常规或 UACR 报告；系统自动识别并只对不确定字段局部确认；先做安全筛查与简洁总览，再通过动态选择题、文字或可打断的实时语音对话补充必要信息；提供有依据的分层医学信息解释、复诊问题、历史报告比较和提醒。用户无需反复手工输入；所有主要功能在普通/老年模式均完整可用。中国大陆普通网络无需 VPN。

## 1. 产品定位与边界

- **名称**：MediLens；项目书名称为「糖尿病尿检报告智能解读与健康陪伴系统」，但**MVP 暂不开发健康陪伴/虚拟宠物**。
- **首期人群（已确认）**：已确诊糖尿病、需要定期复查的患者；同时照顾家庭照护者使用情境，但**MVP 不区分患者/照护者角色**。未来可能扩大人群与报告类型，首期不提前扩张。
- **首期报告（已确认）**：尿常规与尿白蛋白/肌酐比（UACR）。遇到其他报告，应识别类型并友好提示当前不支持，不得强行解读。
- **平台（已确认）**：原生安装体验的 iOS + Android APP；当前无需正式上架，未来可能上架。
- **实际用途（已确认）**：目标是真实用户使用，**不是仅做比赛视频**。因此医学审核、数据保护、监管属性评估是上线前置条件；开发与内部模拟测试可先进行。
- **医疗边界（已确认）**：辅助理解报告、解释指标及组合、提示需要关注的情况、准备复诊问题；不得替代医生诊断，不得建议自行停药、换药、调整剂量；已有医生医嘱优先。医生医嘱与软件提示冲突时，引导咨询医生，不自动改写医嘱。
- **中国大陆网络（已确认）**：终端运行与 AI/OCR/语音/存储所需服务必须能在中国大陆普通网络访问，不依赖 VPN、Google 服务或 OpenAI API。开发人员使用什么编程助手与终端软件能否无 VPN 使用是两回事。
- **明确排除（已确认）**：本版无宠物、无宠物任务打卡；不做所有疾病/所有检验报告；不做自动治疗方案或处方调整；暂不要求完全离线运行；暂不正式发布应用商店；暂不实现家庭角色权限区分和跨设备同步的复杂协作功能。

## 2. 体验原则与优先级

1. **拍照优先、少输入**：自动识别能获得的信息不再问；只对缺失、低置信或安全所需信息提问。
2. **主动引导、逐步问答**：选择题为主要补充方式，选项覆盖合理情况、通俗、简洁；每题有「不确定/不愿透露/跳过」（对必须处理的安全信息要明确说明无法判断，而非默认为阴性）。题数不固定，由规则与上下文决定；不为凑题数提问。
3. **分层解释，不用全局“详细模式”开关**：每条 AI 输出默认短而清楚，旁边可点「详细了解」（建议文案）展开该条内容的原因、指标关联、依据等；保留自由文本输入，但不是主入口。
4. **两种显示模式同等完善**：普通模式与老年模式均能完成全部流程；老年模式调整字号、点击面积、对比度、排版、语音入口等，不删减核心功能。
5. **语音是真对话**：用户自主选择语音模式后，支持连续双向对话、自然中文语音、实时打断（barge-in）、中途改变问题、切回文字时保留上下文。支持高质量朗读，音色与语速等设置集中管理。
6. **设置统一管理**：数据同步内容、OCR 方式、界面模式、音色/语速、通知等常规偏好集中在「设置」；但敏感数据首次上传/处理的法定告知与单独同意不能被隐藏到设置中。
7. **先安全后解释**：识别不确定时不做确定性判断；紧急信号优先提示，不等待长问卷或生成模型；不可把「未知」解释成「正常」。

## 3. 用户类型、账号与数据

### 3.1 游客模式（已确认）
- 无需注册即可拍照、解读、选择题、文字与语音互动（前提是用户同意完成云端 AI 解读所必需的数据处理）。
- **只能使用本地 OCR**：原始报告图像不得被发送给云端 OCR。注意本地 OCR 不等于整个产品离线；如调用云端 AI，应最小化并告知传输的脱敏指标及必要上下文。
- 历史数据可选择仅在本机保存，或不保存；删除应用/换机/清除数据可能导致记录丢失，应明示。
- 不支持账号云同步。

### 3.2 注册用户（已确认）
- 注册/登录用于长期记录管理；推荐注册，但不强制。
- **本地 OCR 或云端 OCR 均可选**；云端 OCR 仅在明确开启、取得相应授权后上传图片。设置中可切换。
- **本地保存为默认策略**；注册**不自动等于上传报告**。
- 用户可在设置中选择云端同步，并细分同步内容（如报告、结构化指标、对话记录）。未选中的内容不得偷偷同步。
- 只有开启相应云同步后，才能承诺换机恢复对应数据；**跨设备同步暂不开发**这一早期回答与后续“注册后可选云端上传”并存：首版应实现**可选云端备份/上传**，而多设备实时双向同步与冲突合并可延后。请在架构/界面中准确区分「备份/恢复」和「实时同步」，不要默认已支持全部能力。
- 允许随时删除单条/全部历史记录；需明确本地、云端、备份、副本、第三方缓存的删除流程与合理边界，提供删除反馈。
- 游客升级注册时，**是否迁移游客本地历史**尚未明确，需设计为可选且不得静默上传。

### 3.3 建议的数据实体（技术设计，不是用户新增需求）
- Account / ConsentRecord / UserSettings / Report / ReportImageLocalRef / LabItem / OCRCandidate / ReviewDecision / AnalysisSnapshot / RuleHit / EvidenceCitation / Conversation / Message / FollowupAnswer / MedicationEvidence / Reminder / AuditLog / SyncPreference。
- 每份报告保留：日期、类型、原始值、单位、原报告参考范围、原文坐标、识别置信度、确认状态、规范化值与转换依据、规则/知识版本。不同医院和检测方法不可直接机械比较。
- 服务器与设备端敏感数据加密、最小权限、数据分区、删除机制、访问日志；API 密钥只在后端，不放客户端。

## 4. 核心页面与操作路径（首版必须覆盖）

### P01 启动与入口
- 首次打开说明核心功能与隐私边界；入口「游客体验」「注册/登录」；不强制先填写病史。
- 主屏突出「拍照解读」，次级「从相册选择」「选择文件」；提供历史记录、语音入口和设置。
- 对非目标报告提供清楚说明；不可伪装为已完成解读。

### P02 拍照/导入
- 相机拍照、相册图片、文件（至少常见图片与 PDF；文件格式白名单需实现并测试）；支持裁剪、旋转、重拍、模糊/反光提示、多页文档。
- 游客始终本地 OCR；注册用户按设置选择 OCR。云端上传前清楚说明原图传输。

### P03 OCR 识别与局部确认（**强制细节**）
- 提取「医院/检验日期/样本类型/项目名/结果/单位/参考范围/异常标记」；项目书采用「项目—结果—单位—参考范围—异常标记」为模块接口。
- 对低置信度或逻辑冲突的字段，**在原始报告图像的正确坐标绘制高亮框**，可点击局部放大；在旁边展示候选结果供点选，例如「尿蛋白 PRO：1+ / 2+ / 其他 / 无法确认 / 重拍」。
- 多个不确定字段逐项处理，显示「第 x/y 项」；**不得要求用户重新手填整张报告**。
- OCR 候选不可信时不能强迫二选一；「其他」可通过重新拍照或局部手工更正作为兜底；无法确认的字段标记 unknown/excluded，不用于依赖该值的确定性规则。
- OCR 置信度高但单位、参考范围、数值明显矛盾，也应触发复核。
- 重要：OCR 的文字框坐标必须与原图/旋转裁剪后的坐标系一致，避免框错行。

### P04 解读总览
- 在足够可靠的数据基础上展示重点：已识别项目数、需关注项目、无法确认项目、初步风险提示及数据完整性。
- 红黄绿为**经过医学审核后**的提示体系：项目书的示例等级与阈值不可直接用于真实患者。高风险提示置顶；未知数据不自动变绿。
- 初始总览先展示，不要求用户完成长问卷才能看到已知信息；如存在必须及时处理的危险症状提示，立即优先展示。

### P05 动态选择题
- 根据已识别结果和先前回答，针对用药、症状、感染、饮食等因素选择性提问；不设固定题数。
- 例（仅演示交互，**非经审核的临床算法**）：当需要了解 SGLT2 类药物使用情况，询问「您是否正在使用某类降糖药？」选项包括「知道名称 / 正在用药但不清楚 / 没有 / 不确定 / 不愿透露」，必要时引导药盒拍照。
- 每题尽量单一主题，允许跳过；多选/单选依据问题语义；动态跳转必须可回退更改答案；不可假设未回答即无症状。
- 问答结束或用户退出时保留当前已知状态，更新解释并标注哪些结论受缺失信息影响。

### P06 逐条解释与对话
- 每条解释默认短句、通俗；旁边「详细了解」可原位展开指标定义、可能干扰、组合关系、医学依据、复诊提问；「朗读」按钮可听自然中文。
- 可输入自由文字，但不是主要操作；常用快捷问题如「这个指标是什么」「哪些指标有关」「复诊问什么」。
- 对话由结构化事实、经审核规则和可核验知识约束；模型不得新增未经规则支持的风险结论。
- 用户问「能停药吗」「是不是肾衰竭」等，明确边界并引导医生评估；不得仅靠关键词过滤，要结合上下文与安全模板。

### P07 实时语音模式
- 用户主动进入，双向连续语音，支持自然打断、停止播报、转话题、静音/退出、文字模式切换；语音与文字共享同一报告和会话状态。
- 对重要医疗提示必须**同步显示可阅读文字**，不能只口头播报。
- 高质量语音需要实际主观听感测试（自然度、音色、停顿、响应延迟、老人可听清程度）；选择中国大陆可访问的 ASR/TTS/实时音频服务，支持弱网、断线、权限拒绝降级到文字。
- 语音打断不能使安全提示丢失；被打断的输出要能查看文字摘要。

### P08 药盒/处方辅助识别
- 用户可拍摄药盒/处方辅助识别名称、可能类别，**需确认**；解释经审核的药物类别与尿检指标可能关联。
- 不自动给出停药/换药/加减剂量方案；以医生意见优先。识别不确定时不能猜药名。

### P09 历史记录与趋势
- 按报告日期排序，支持搜索/查看、单条或批量删除；上传新报告后对可比指标自动生成趋势。
- 显示不同报告日期、单位、方法、参考范围和确认状态；不可比时提示「不可直接比较」，避免仅凭 ±→1+→2+ 等等级做不受条件约束的临床推断。
- 注册用户按同步偏好决定是否上传；游客仅本地可选存储。

### P10 复诊问题与提醒
- 自动汇总可向医生询问的问题，可复制/保存；明确不是处方或诊断。
- 支持复查提醒，但时间来源须是用户确认的医嘱或经审核的规则；不凭大模型自由决定复查间隔。
- 系统通知权限由用户决定，设置集中管理。

### P11 设置中心（统一管理）
- 账号与登录；隐私与数据（本地/云端、同步哪些内容、删除/导出与授权记录）；OCR 方式（游客只能本地）；显示（普通/老年、字号等）；语音（音色、语速、自动朗读、麦克风）；提醒；产品说明与医疗边界。
- 不在各页面散落重复的常规偏好开关；**但第一次敏感数据云端处理需要在动作发生前取得适当授权**。

## 5. 医学与 AI 系统的分工（不可混淆）

**项目书的核心流水线**：图像预处理/OCR → 标准化 → 确定性规则 → 知识检索（RAG）→ 大模型通俗表达 → 数值/出处/越界校验 → 分层交互 → 归档。

### 5.1 OCR 与标准化
- 尽量从报告读取自身参考区间；保留原值、单位、参考区间和来源。支持同义词映射（GLU/尿糖、KET/尿酮体、PRO/尿蛋白、UACR 等），但映射与单位转换需要测试。
- UACR 等单位转换、定性分级与可比性规则需独立验证；不允许模型随意计算或改写原值。
- 识别置信度与医学规则置信度是两件事；任一关键字段缺失都要可追溯。

### 5.2 规则引擎
- 规则以可版本化的 JSON/YAML 或数据库记录维护；包括输入条件、缺失数据处理、优先级、风险级别、解释模板、证据来源、审核状态。
- 项目书列有 R-01 至 R-06 示例（尿糖/尿酮体、SGLT2、UACR 与感染、趋势等），**只是候选规则，未完成医学审核**；不得直接作为对真实患者的可靠诊断或分流依据。
- 规则判读与大模型语言生成分离；若规则未覆盖，输出「无法据此判断」，不允许大模型擅自补结论。
- 高风险情形须有经审核的安全处理模板；开发期先用明确标识的模拟规则进行端到端测试。

### 5.3 知识库与 RAG
- 老师未来会提供医学资料（**目前尚未实际收到**）。正式知识库需记录来源、标题、版本/年份、段落、适用范围、授权状态、审核状态。
- 可以先建立知识库导入/检索框架，使用可合法使用的占位测试知识；**不得伪造指南原文、页码、医学引用**。
- 检索结果用于解释既有规则，不能替代规则决定红黄绿。输出每条关键医学说明的可核验来源；检索不到时明确说明并使用审核模板或不回答。

### 5.4 输出校验与降级
- 数值必须与已确认结构化数据一致；检查单位、引用存在性、规则结论一致性、禁用用药建议、危险情况提示优先级。
- AI/检索失败时使用经审核的静态说明或明确提示服务不可用；不得编造成功结果。
- 所有结果显示「辅助理解、不能替代医生」的适当提示，但免责声明不能代替产品安全性验证。

## 6. 技术架构：建议方案，非已选型

**目标结构**：Flutter（或经团队评估的同等跨平台框架）移动客户端 + 本地安全存储/本地 OCR + 中国大陆可访问的 API 后端（可选 FastAPI） + 规则引擎 + 国内模型服务 + 可审核知识库 + 数据库/对象存储（云同步仅在用户开启时）。

- **端侧**：相机/相册/PDF 导入、图像预处理、本地 OCR、原图坐标框选、音频采集播放、加密本地数据库、设置与用户界面。
- **后端**：鉴权、最小化数据接口、规则执行、RAG 检索、模型调用、输出校验、可选云端 OCR、语音服务适配、加密存储与删除任务。
- **模型接口**：设计 provider adapter，支持替换不同中国大陆可访问的模型，不把模型厂商与核心业务逻辑硬编码耦合；不得在客户端放密钥。
- **数据库**：可考虑 PostgreSQL + 对象存储；向量检索是否使用 pgvector/FAISS 等需依据知识规模决定。真实 API/SDK、价格、可用区、音频中断能力均需查询官方文档并做实测。
- **网络兼容**：测试中国大陆不同网络下的登录、OCR、AI、语音、文件上传、通知；无 VPN；禁止在依赖链暗藏境外 CDN/Google 服务。
- **隐私**：图片、结构化检验数据、语音流、对话记录、账号标识是不同数据类型，分别梳理是否离端、是否保存、保存多久、谁可访问、用户如何撤回授权。

## 7. 关键接口与状态机（供开发模型直接落地）

### 7.1 数据示例（仅为接口草案）
```json
{
  "report_id": "example-001",
  "report_type": "urinalysis",
  "test_date": "2026-10-01",
  "items": [
    {
      "code": "PRO",
      "original_label": "尿蛋白",
      "raw_value": "1+",
      "unit": null,
      "reference_text": "阴性",
      "ocr_confidence": 0.61,
      "review_status": "needs_confirmation",
      "image_box": {"page": 1, "x": 0.55, "y": 0.42, "w": 0.12, "h": 0.04},
      "candidates": ["1+", "2+"],
      "normalized_value": null
    }
  ]
}
```
说明：图像坐标采用归一化示意值，正式接口需定义旋转、裁剪、分页后的坐标基准；示例数据不是临床事实。

### 7.2 状态流（建议）
`idle → capture/import → quality_check → OCR → review_required? → structured_ready → rules_screened → initial_summary → optional_followups → explanation_updated → save_choice → history/reminder`

并行子状态：`voice_off / connecting / listening / thinking / speaking / interrupted / reconnecting / failed`。当用户打断时，停止当前音频并保留已确认的结构化数据、当前问题和必要安全提示；不可丢失或重置报告。

### 7.3 动态问题数据（建议）
每题应有 `question_id`、`trigger_rule`、`plain_language_prompt`、`options`、`allow_unknown`、`allow_decline`、`allow_skip`、`answer_type`、`next_question_logic`、`medical_rationale`、`review_status`；不能让大模型无约束地随意产生医学分流问题。

## 8. 必须覆盖的异常/边界场景

- 拍摄模糊、反光、歪斜、裁剪不全、报告跨页、PDF 无文字层；支持重拍与提示。
- OCR 将 `±` 识别成 `+` 或 `-`、`1+` 与 `2+` 混淆、列错位、参考区间漏读；局部框选+候选确认。
- 无法确认某项、报告缺失参考范围、单位不一致、多个医院使用不同名称、日期识别错误。
- 游客不注册、游客不保存、游客关闭 APP、游客升级注册；不能静默上传本地历史。
- 注册但不开云同步、只同步报告不传对话、云端 OCR 关闭、撤回云同步授权、删除单份/全部记录。
- 手机断网、弱网、语音权限拒绝、实时语音被打断、服务端超时、AI 失败；可退回文字与已审核的静态信息。
- 上传非尿检报告、药盒名称识别不确定、用户问停药/换药/确诊、用户提供与报告冲突的描述。
- 老年模式全流程、辅助功能/屏幕阅读器、较大字体、小屏幕；功能与普通模式同等完整。
- 历史报告缺少可比条件时不画误导性趋势；删除后历史图表和关联对话更新。

## 9. 测试与验收：必须可复现

### 9.1 初期测试资料
- 先使用**明确标注为合成**的尿常规/UACR 报告，覆盖正常、异常、混合、缺项、错位、不同版式、多个日期、药物相关干扰等场景。
- 未来通过老师取得适当授权/脱敏的真实报告，再做真实环境验证。**合成报告测试通过≠真实识别准确率达标**。
- 项目书提出的 OCR ≥95%、风险规则召回率 100%、端到端 ≤15 秒等是**原型目标，不是已经达到的成绩或对真实患者的安全保证**。

### 9.2 功能验收（示例）
1. 游客拍摄合成尿检报告→本地 OCR→局部确认→查看总览→动态问答→查看「详细了解」→不保存退出，全流程无需注册。
2. 注册用户关闭云 OCR 和云同步→本地识别、本地保存，抓包/日志验证原始报告图像未发送云端 OCR。
3. 注册用户开启云 OCR→获得适当告知授权→识别→设置中关闭云 OCR；验证后续报告不再上传云 OCR。
4. 识别 PRO `1+`/`2+` 模糊→原图准确框选→用户选择→后续规则读取确认值；选「无法确认」时该值不进入依赖规则。
5. 动态选择题可跳过/回退；未知答案不当作否定；用户回答改变时解释更新且保留证据。
6. 语音模式持续对话，AI 播报中用户插话→停止旧播报、识别新问题、保持报告上下文；断网后可退出至文字。
7. 单条解释点「详细了解」→仅展开该条，不强制切换全局模式；朗读内容与文字一致。
8. 两份可比历史报告自动展示趋势；不可比报告显示限制；删除一份后图表与列表同步变化。
9. 云端仅同步用户选定的数据类别；关闭后停止新增上传；删除行为可查证。
10. 模拟高风险规则在审核前只能显示测试标识，不向真实患者发布未经审核的处置结论。
11. 普通/老年模式在 iOS 与 Android 完成同一组关键任务，语音/设置/删除等入口均可达。
12. 大陆普通网络实机测试，不依赖 VPN；所有第三方服务端点有清单及失败降级方案。

### 9.3 验收报告格式
每一模块记录：需求编号、实现文件、运行命令、测试设备、输入样本、预期结果、实测结果、截图/日志、已知问题、风险等级、下一步；**不能把未测写成已通过**。

## 10. 分阶段执行计划（建议，不擅自砍功能）

- **阶段 0：需求冻结与技术验证**：读取项目书+本文件，核对矛盾；评估本地 OCR、云 OCR、实时语音打断、国内模型服务、iOS/Android 构建与数据方案；输出最小阻塞问题清单。
- **阶段 1：完整端到端核心链路**：双端 APP 框架、游客模式、本地 OCR、局部确认、合成报告、规则引擎测试版本、总览、分层解释、动态选择题、文字对话。
- **阶段 2：语音与药物**：实时语音、打断、高质量播报、药盒/处方辅助识别、语音文字上下文同步。
- **阶段 3：账号与长期记录**：注册登录、本地加密存储、历史趋势、复诊问题、提醒、用户可选云 OCR/云备份、数据删除和设置中心。
- **阶段 4：医学与安全验证**：老师提供知识资料并审核规则、引用与风险提示；真实脱敏报告测试、弱网/隐私/安全测试、监管属性和合规路径评估。
- **阶段 5：面向真实用户的受控发布**：仅在医学、数据保护和必要监管要求完成后开展真实用户试用。内部合成演示不等于上线许可。

注意：以上是实施先后顺序，**不是把阶段 2/3 已确认功能从 MVP 中删除**。模型可提出更合理的依赖顺序，但必须解释影响并经团队确认。

### 待医学/技术验证（**不要当成已解决**）
- **医学**：具体规则阈值、红黄绿等级与措辞、症状触发、药物关联、复查提醒依据；老师是否正式承担审核、审核时间、版本签署。
- **技术**：两端本地 OCR 对多版式中文报告的可行性、云端 OCR/语音服务选型、中文实时打断效果、语音听感、国内网络稳定性、成本与部署条件。
- **数据/账号**：注册方式（手机号/邮箱/其他）、游客升级时是否迁移数据、云端备份恢复的具体 UX、删除备份的策略、保存期限、原始图像是否本地持久保存、云端同步是否包含原图（需单独选项）。
- **运营/合规**：隐私政策、单独同意、服务协议、敏感信息处理、未成年人策略、数据跨境风险、软件医疗器械管理属性及相关要求；真实患者试用前需专业核验。
- **范围解释**：用户明确说「D5 暂不开发多设备同步」，又要求注册后可选择云端上传；按“可选云端备份，不承诺实时多端双向同步”暂定，若产品负责人有不同理解再确认。

- **视觉**：暖橙色只是旧项目示意，可保留也可重新设计；不应把旧稿配色当作硬性品牌规范。

### 非阻塞事项的默认处理
