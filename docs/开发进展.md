- 新增 `scripts/dev-env.ps1`：一键加载 flutter/java/adb/emulator 环境变量与国内镜像（仅开发环境）。
- 后端（FastAPI）：
  - `normalize`：同义词映射、定性分级（阴性/±/1+…4+）、UACR 单位换算（mg/mmol→mg/g，系数待审核）、参考范围比对、矛盾检测（数值不合理、单位缺失/无法识别、异常标记与范围不一致）。

  - API：`/api/v1/health`、`/api/v1/analyze`、`/api/v1/followup/validate`。

- `knowledge`：占位知识库 `kb_test.yaml`（**开发团队自编，非指南原文，未经审核**），按指标代码与关键词检索；检索不到明确返回「无法据此回答」。

## 迭代 3｜2026-10-24｜合成报告、端侧 OCR、Flutter 客户端全流程、端到端测试

### 做了什么
- **合成报告**：`tools/gen_synthetic_reports.py` 生成 9 份合成报告（正常、尿糖+酮体、尿蛋白被遮挡、UACR+感染、mg/mmol、缺参考范围、肝功能、横置、模糊），图上带「合成测试样本」水印，附标注 JSON。
- **OCR 可行性验证**：`tools/ocr_reference.py`（Python + ONNX Runtime）在合成报告上验证 PP-OCRv5 识别准确（大部分字段置信度 >0.99）；导出 OCR 结果供 Dart 解析单测使用。
- **端侧 OCR（Dart）**：检测前后处理（连通域、外扩、坐标映射）、CTC 解码、自动判断横置并旋转、图像质量检查（模糊/偏暗/反光/分辨率）；报告解析（行聚类、表头定位列、合并单元格拆分、同义词映射、日期识别）；低置信（<0.95）与矛盾字段（单位缺失/无法识别、数值不合理、阴性带↑、未识别结果）进入局部确认并生成易混淆候选。
- **Flutter 客户端页面**：P01 启动（游客/注册待实现、老年模式开关）、主页（拍照/相册/文件（图片+PDF 首页）/合成示例）、P02 导入预览（质量提示、旋转、重拍）、P03 局部确认（原图高亮框、局部放大、候选、其他手动更正、无法确认、重拍、第 x/y 项）、首次解读前单独告知同意、P04 总览（紧急提示置顶、测试规则标识、计数、受缺失信息影响的结论）、P05 动态选择题（跳过/不确定/不愿透露/上一题）、P06 逐条「详细了解」原位展开 + 朗读 + 文字对话（快捷问题）、保存选择（本机加密/不保存）、P09 历史（删除单条/全部）、P10 复诊问题（复制）、P11 设置中心；P07 语音、P08 药盒、注册登录、提醒为「待实现」页。
- **本地加密存储**：SQLCipher，密钥存系统安全存储；不保存原图。
- **网络合规**：`tools/check_network.py` 扫描源码与 APK；新增 `docs/网络请求清单与大陆网络测试.md`。
- README 补全安装、启动、测试命令。

### 发现并修复的问题（均由测试发现）
- 老年模式主题放大字号时断言崩溃（基础字体无字号）→ 并入 Material 字号几何后再缩放。
- Android 9+ 默认禁止 HTTP 明文，调试版无法连接开发机后端 → 仅调试版允许明文；正式版要求 HTTPS；主清单补 INTERNET 权限。
- 检测器把相邻两列合成一个框（「mg/mmol <3.4」）→ 按空格拆分并按字符位置估算列。
- 「↑」箭头检测不稳定 → 判读不依赖箭头，只依赖参考范围比对。
- Windows 跨盘（项目 D: / 缓存 C:）Kotlin 增量编译失败 → 关闭 Kotlin 增量编译。
- NDK 未自动安装 → 手动安装 NDK 28.2。
- iOS Info.plist 补充相机/相册/麦克风权限说明。

## 迭代 14｜2026-11-03｜参考 iThink 智能体工作流的两项改进
结论：MediLens 已是固定编排的「智能体工作流」（意图分类→条件分支→知识检索→LLM 生成→校验），与 iThink/Dify 课程范例同构；不改为自主决策的 Agent，以保持医疗判读可预测、可追溯。借鉴两点：
1. **去除推理模型的思考过程**（`llm.strip_thinking`）：DeepSeek 等会把 `<think>…</think>` 放进正文，导致意图误判或校验失败而全部回退；只有思考、没有回答时视为失败。大模型意图分类只采信唯一明确的标签（解释句中出现多个标签时不采信）。
2. **多轮追问的指代补全**（对应 iThink「优化 Query」，但为确定性规则、不增加一次大模型调用）：问题未点名指标且指回前文（它/这个/那…/为什么…）时，沿用最近一次提问中的指标再检索与起草；追问时结合上一句提到的药物判断用药决策；大模型生成与意图分类都看到最近对话（注明仅用于理解指代）。此前客户端已发送对话记录，但后端未使用。
- 测试：后端 183 passed（新增 18 项）。

### 实验 E：问答提示词三版对比与两处问答缺陷（2026-11-03，`tools/eval/exp_e_prompt_compare.py` → `tests/eval/exp_e/`）
实验 D 的 MediLens 组主要是规则总览，大模型只参与停药提问（走安全模板），无法反映问答提示词的变化，因此新增实验 E：40 份合成报告各配一个常见问题 + 10 组多轮追问，走真实问答流程（DeepSeek-V4.1-Flash），只替换提示词；Qwen3.8-Flash 对照「报告 + 规则结论」评审。
- **第一轮发现两处缺陷（与提示词无关）并已修复**：① 有紧急提示（尿糖+尿酮体）的报告，问其他问题时回答只有 20–30% 保留就医提示 → 草稿一律带上就医提示，大模型省略时确定性补回，修复后 100%；② 「这份报告我最需要注意什么」10 次中 7 次回答「暂无可核验资料」→ 扩充整份报告问法，修复后矛盾率由 10–16% 降为 0–6%。
- **三版提示词（第三轮，各 50 题）**：回答了所问 94% / 94% / 98%（旧「只改写」/ 组员「直接回答」/ 折中）；越界用药与断定诊断均为 0；紧急报告就医提示均 100%；「新增规则外结论」12% / 6% / 8%，但第二、三轮间旧版与组员版数值互换（8%↔14%），说明 50 题下差异主要是随机波动，且多数被标记的是知识库原有内容（评审误判）。
- **决定采用折中版**：保留「先回答所问」，并明确「只能使用草稿与报告事实中已有的说法、不得自行推断病情或器官损害（如肾损伤、肾病、感染、血糖控制差）、不得新增饮食或用药建议」。
- 已知不足：「复查前要注意什么」的草稿总是取 UACR 复查资料，即使报告没有 UACR；评审为单一模型，需人工抽查 outputs.json。
- 测试：后端 192 passed。

## 迭代 15｜2026-11-03｜问答的受控工具调用（检索规划，`backend/app/planner.py`）
定位：介于固定工作流与自主智能体之间——大模型只负责「读懂问题、从固定工具中挑要查什么」，工具由程序执行，医学结论仍来自规则与知识库。
- 工具 7 个：item（指标含义与本次结果）、rule（某条提示）、overall（整份报告）、trend（与以往报告比较，高低由程序计算，不解读意义）、drug（药物对该指标的影响，只用标注了该指标的资料）、prep（检查/复查前注意事项）、relation（指标间关系，只用本次共同触发的提示）。
- 约束：参数只能是本次报告的指标代码与命中的提示编号，非法工具/参数丢弃，最多 3 个；规划失败时沿用规则路由。安全判断不变（关键词 + 专门的意图分类器优先，规划结果不参与）；紧急报告的就医提示照常补回。
- 速度：规划与原有流程并行；只有规划带来规则路由没有的资料时（新类型工具或未覆盖的指标）才多生成一次回答。
- **实验 F**（`tools/eval/exp_f_planner.py` → `tests/eval/exp_f/`，第二轮）：难题 24 题（药物影响、与上次比较、含糊整体、检查前、指标关系、下一步）回答了所问 54% → **100%**，「无资料」50% → 0；常规 50 题 96% → 98%；越界用药与断定诊断均 0，紧急就医提示 100%。代价：常规题耗时中位数 3.2 → 5.1 秒、最大 16 秒（84% 的常规题选到新资料，多为 prep/relation，属正确选择）。「新增规则外结论」难题 13%，被标记的多为知识库原文（评审误判），需人工抽查。
- 测试：后端 203 passed。尚未部署到服务器、未在 APP 上实测。
